## 核心心智模型：分层架构

```
┌─────────────────────────────────────────────┐
│  UI 层（main.py 双模式框架）                 │
│  验收模式(默认)  ⇄ F12 ⇄  调试模式(三 tab)   │
└───────────────┬─────────────────────────────┘
                │ 事件入队 / 主线程 on_tick 消费
┌───────────────▼─────────────────────────────┐
│  业务层（无 tk 依赖，可单测）                 │
│  accept_core(判定) + accept_report(报告)      │
│  points_lib(点位) + persist(持久化)           │
└───────────────┬─────────────────────────────┘
                │ 线程安全调用
┌───────────────▼─────────────────────────────┐
│  通讯层（工作线程）                           │
│  pyserial(DL/T645) + pymodbus(Modbus)        │
│  + paho-mqtt(MQTT)                           │
└─────────────────────────────────────────────┘
```

**核心原则**（详见 [[1-Swj-项目概览与架构]]）：

1. **网络/串口回调绝不直接碰 tk 控件** —— 回调只 `queue.put()`，主线程 `on_tick()` → `_drain_queue()` 才动 UI
2. **判定逻辑与 UI 分离** —— `accept_core.py` 纯 Python，可独立 pytest 单测
3. **数据驱动** —— 点位/命令/字段/错误码全部集中在 `points_lib.py`，界面只做展示与下发
