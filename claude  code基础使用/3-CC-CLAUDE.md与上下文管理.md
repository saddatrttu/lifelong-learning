## CLAUDE.md 是什么

`CLAUDE.md` 是放在项目里的 Markdown 文件，相当于 Claude 的"**行为宪法**"：

- 每个**新会话自动加载**（以用户消息形式注入 context，优先级高于一般指令）
- 写一次、以后每次都照着办
- 与对话中临时交代的区别：临时的话说完这轮就忘，CLAUDE.md 长期有效

> 它是行为规范层，不是 README。Claude 在整个对话中持续遵守，不是"希望它参考"。

---

## 三层作用域

| 层级   | 路径                                                                                                                                               | 共享方式                | 适用场景            |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------- | --------------- |
| 组织级  | macOS：`/Library/Application Support/ClaudeCode/CLAUDE.md`；Linux/WSL：`/etc/claude-code/CLAUDE.md`；Windows：`C:\Program Files\ClaudeCode\CLAUDE.md` | IT/DevOps 强制部署      | 公司编码标准、安全策略     |
| 用户级  | `~/.claude/CLAUDE.md`                                                                                                                            | 个人（所有项目）            | 个人偏好、常用工具       |
| 项目级  | `./CLAUDE.md` 或 `./.claude/CLAUDE.md`                                                                                                            | 版本控制（团队共享）          | 项目架构、构建命令、代码规范  |
| 本地个人 | `./CLAUDE.local.md`                                                                                                                              | 本地仓库（加入 .gitignore） | 个人沙箱 URL、本地测试数据 |

**合并规则**：从根目录向下逐层加载所有 CLAUDE.md，**较深层的指令优先级最高**（最后读）。所有文件拼接而非覆盖；若冲突，Claude 可能任意选择其一——**要定期检查、排除矛盾指令**。

**典型场景**：
- 团队规范放项目 `CLAUDE.md` 并 commit 进仓库，全团队共享
- 个人偏好（如回复语言、commit 风格）用 `CLAUDE.local.md` 覆写，不要改团队的
- 大型 monorepo 可用 `claudeMdExcludes` 配置跳过无关团队的指令

## 用 /init 初始化

```bash
claude
/init
```

`/init` 会自动扫描项目并生成初始 CLAUDE.md（含构建测试命令、项目约定、文件架构）。若已存在，会建议改进而非覆盖。也可以直接让 Claude"把这条规则写进 CLAUDE.md"。

## 该写什么

最值得写进去的几样东西：

| 类别               | 示例                                        |
| ---------------- | ----------------------------------------- |
| **构建和测试命令**（最值钱） | `npm run build`、`pytest src/`——省得它每次瞎猜怎么跑 |
| **代码风格**         | 缩进、命名、import 顺序                           |
| **架构决策**         | 模块怎么分、API 原则、关键依赖                         |
| **容易栽跟头的地方**     | 已知坑、环境特殊性                                 |
| **反复交代的流程**      | "提交前跑 linter"、"改完同步文档"                    |

按 **WHY → WHAT → HOW** 组织：

- **WHY**（为什么）：项目是做什么的？解决什么问题？
- **WHAT**（是什么）：技术栈、目录结构、关键模块
- **HOW**（怎么做）：用什么工具、怎么跑测试、怎么验证改动

## 不该写什么

| 不要放 | 原因 | 替代方案 |
|--------|------|---------|
| 完整 API 文档 | 太长、占 context、易过时 | 指向文档链接 |
| 代码风格细节 | 浪费 token，格式化交给工具 | ESLint / Prettier / Biome |
| 工作流步骤 | CLAUDE.md 该保持轻量 | 用 [[4-CC-Skills与子代理\|Skills]] |
| 只在特定任务有用的指令 | 不应常驻上下文 | 按需加载的 Skills |
| 敏感信息 | 项目 CLAUDE.md 会 commit 进仓库 | 绝不写入密钥 |

**指向而非复制**：引用具体文件路径（如 `src/lib/auth.ts:42`）比粘贴代码更好，因为代码会变，副本很快过时。

## 路径作用域 .claude/rules

`.claude/rules/` 目录可以做**路径作用域**——规则只在处理对应路径时才加载：

```
.claude/rules/
├── frontend.md   # 只在处理 src/frontend/ 相关文件时加载
└── backend.md    # 只在处理后端相关文件时加载
```

匹配逻辑基于子目录名称。这让 CLAUDE.md 从"静态文件"进化为"**动态规则引擎**"，大幅减少无关规则占用 context。

> 超过 300 行的 CLAUDE.md 建议拆分到 `.claude/rules/` 做路径作用域。

---

## 最佳实践

1. **最关键的规则放最顶端**（首因效应），总长度控制在 **200–500 行**以内
2. 顶部放关键规则 → 中间放工作流程 → 底部放参考信息
3. 不要复制代码，用路径引用
4. CLAUDE.md 放"必须始终知道的"；Skills 放"有时需要的"（详见 [[4-CC-Skills与子代理]]）
5. 团队项目：CLAUDE.md 提交进仓库，个人偏好用 `CLAUDE.local.md`
6. **规则**（不变量）→ CLAUDE.md；**学习记录** → Auto Memory；**临时状态** → Session Memory 自动处理

## 上下文管理

### 加载顺序

每个新会话按此顺序加载：

```
系统提示 → 自动记忆 MEMORY.md（前 200 行或 25KB）
→ 环境信息 → MCP 工具列表 → Skill 描述清单
→ 用户级 CLAUDE.md → 项目 CLAUDE.md → 路径作用域规则
```

### 上下文耗尽怎么办

| 命令 | 功能 | 何时使用 |
|------|------|---------|
| `/context` | 查看当前 Token 使用量 | 定期检查成本 |
| `/clear` | 完全清空对话记忆 | 切换到全新任务 |
| `/compact [保留内容]` | 高密度压缩历史 | 保留关键决策并释放空间 |

### 防止 Context Rot

上下文窗口填满后 AI 推理能力显著下降。三个关键习惯：

1. 每次工作前用 `/context` 查看 Token 用量
2. 切换任务时 `/clear` 完全清空
3. 复杂任务前先用计划模式确认架构

## 记忆系统

Claude Code 有三套记忆系统，**混用会让行为不可预测**：

| 系统 | 内容 | 管理方式 |
|------|------|---------|
| CLAUDE.md | 行为规则、禁止事项、架构 | 手动维护 |
| Auto Memory（MEMORY.md） | 跨会话学习记录（规则+动机+场景） | Claude 自动累积、自动加载 |
| Session Memory | 当次会话状态 | 自动处理 |

**分工建议**：
- 规则和规范 → CLAUDE.md
- Claude 的学习记录（如"这个项目的 build 会在 M1 上失败"）→ Auto Memory
- 临时状态 → 交给 Session Memory

高级配置（settings.json）：`autoMemoryDirectory` 自定义记忆位置；`claudeMdExcludes` 排除特定 CLAUDE.md。大多数情况无需改动。
