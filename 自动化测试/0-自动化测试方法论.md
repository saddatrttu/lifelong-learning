## 核心心智模型：测试金字塔

```
         ▲        UI 自动化（Appium）
        / \       少而精，慢、脆、成本高
       /   \
      /     \     服务/接口测试（pytest + API）
     /       \    中等数量，快而稳
    /         \
   /___________\  单元测试（pytest）
  底层多而快，覆盖核心逻辑
```

**三层分工**（详见 [[1-Test-测试方法论核心]]）：

| 层 | 工具 | 数量 | 速度 | 成本 | 职责 |
|----|------|------|------|------|------|
| 单元测试 | pytest | 最多 | 极快 | 最低 | 验证函数/模块逻辑 |
| 接口测试 | pytest + requests | 中等 | 快 | 中 | 验证 API 契约与业务 |
| UI 测试 | Appium | 最少 | 慢 | 最高 | 验证端到端用户路径 |

**核心原则**：底层多、上层少。不要把 80% 的用例堆在脆弱的 UI 层。
